# sat-ar (Glint)

A browser AR satellite tracker: sky map, planetarium and camera AR views of
the satellites overhead, with pass predictions. Started Oct 2026 from
`docs/PLAN.md` and `docs/OPTIONS.md`, which hold the original plan and the
options considered; this file records what was actually built and why.

## Status

Built: data pipeline, core maths (checked against Skyfield), propagation
worker, map / sky / AR views, info card, passes list with calendar export,
search, settings, calibration, night mode, PWA (manifest, icons, service
worker, offline), satellite trains (drawn and listed), "What's that?"
identification by following a light in AR. Unit tests and Playwright end-to-end tests are green; CI and
Pages workflows are written but **the repo has not been pushed** and has no
GitHub remote. AR has only been exercised in headless Chrome, driven by synthetic
`deviceorientationabsolute` events (`e2e/ar.spec.ts`): that proves the
pipeline is self-consistent with the W3C Euler-angle definitions, but **it
still needs testing on real Android and iOS phones.**

```bash
npm run check                 # eslint + tsc (both projects) + vitest
npm run e2e                   # Playwright, system Chrome, fixture data
npm run data -- --cache-only  # rebuild packs from .cache/data, no network
```

## Layout

- `src/core/` — pure maths, no DOM. Everything here is unit-tested.
- `src/data/` — the pack format (`pack.ts`, shared with `scripts/`) and loading.
- `src/worker/` — `engine.ts` (pure, tested) and the worker shell around it.
  `layout.ts` is the tick-buffer layout, separate so the UI thread can read
  buffers without bundling SGP4.
- `src/sky/` — projections and the canvas renderer.
- `src/sensors/` — orientation (`orientation-math.ts` pure and tested;
  `orientation.ts` the browser APIs) and camera.
- `src/state/` — signals: settings (persisted), clock, observer, tracker
  (worker glue), view, AR session, calibration.
- `src/ui/` — Preact components.
- `scripts/` — Node scripts run directly with type stripping (no build step).
- `tools/reference/` — Python/Skyfield reference generator (not run in CI).
- `e2e/` — Playwright tests; `e2e/fixtures/data` is generated by
  `scripts/make-e2e-data.ts`.

## Conventions

- **Imports name their `.ts` extension** everywhere, and only erasable TS
  syntax is allowed (`erasableSyntaxOnly`: no enums, parameter properties or
  namespaces), so Node runs `scripts/` and imports from `src/` without a
  build. JSON imports need `with { type: 'json' }` for the same reason
  (Playwright's tests import `src/core/fixtures` through Node's loader).
- ENU everywhere (x east, y north, z up); azimuth from north through east;
  quaternions `[w, x, y, z]` acting as v' = q v q*; camera looks down −z with
  y up — the W3C device frame, so a screen→Earth quaternion *is* the camera.
- Tolerances in reference tests are set just above the measured error (and
  the look test also asserts the error isn't far *below* its tolerance), so a
  regression can't hide in slack. Re-measure before loosening one.
- ESLint lists both tsconfigs explicitly: the project service only finds
  files named `tsconfig.json` and missed `vite.config.ts`, `scripts/`, `e2e/`.

## Decisions

- **Name "Glint"** is provisional (OPTIONS.md's suggestion); it lives in
  `src/app-info.ts`, `index.html` and `public/manifest.webmanifest`.
- **Preact + signals** for panels; the render loop reads signals with
  `.peek()` so 60 fps drawing never re-renders components.
- **Data packs, not raw OMM.** CelesTrak sends no CORS headers, so browsers
  can't fetch it anyway. Packs are positional rows with a `fields` header
  (old clients survive added columns); Starlink is 2.3 MB raw, 560 KB gzipped.
  Pack files are content-hashed (`starlink-<hash>.json`) so the service worker
  caches them forever and only revalidates `index.json`.
- **Download freshness is tracked in `.cache/data/downloaded.json`**, not file
  times: CI restores the cache from an archive and restored mtimes could make
  week-old data look fresh forever.
- **CelesTrak rate-limits hard.** During development (Oct 2026) it started
  answering 503 after ~20 requests in a few minutes; the optional packs
  (constellations, gnss, weather) were missing from the local build for that
  reason. Don't loop fetches against it; use `--cache-only`.
- **Magnitudes**: McCants where listed; per-family defaults for Starlink
  (5.5), OneWeb (7.5), Kuiper (6.5); else a fit of McCants' magnitude against
  log RCS (slope −2.49, rms 0.89 mag); else unknown. The model is the
  half-phase sphere formula McCants' list assumes.
- **"Visible"** = above 10°, ≥ half sunlit, Sun ≤ −6° (Heavens-Above's
  convention, so its tables can check ours). The live views use a looser
  sky-darkness test (Sun ≤ −4°, `DARK_ENOUGH_SUN_EL`) plus a limiting
  magnitude that brightens with twilight.
- **Pass search skips ahead** by a conservative bound on how soon the
  satellite could rise (geocentric angle to the horizon circle ÷ peak angular
  rate). The engine reuses the same bound to skip propagating satellites deep
  below the horizon; `engine.test.ts` checks over two hours of 5 s ticks that
  no risen satellite is ever skipped.
- **Ticks are back-pressured** (one in flight, ≥ 250 ms apart at 1×) and the
  renderer extrapolates linearly from each tick's ENU velocity. At high time
  rates the error grows (curvature: ~16 km after 60 s), which is fine for a
  fast-forward preview.
- **iOS heading**: Apple defines `webkitCompassHeading` as the spec's absolute
  alpha (heading = 360 − α). We take attitude from the smooth relative gyro
  angles and pull a heading offset toward the compass with a 3 s time constant
  (`HeadingOffset`). Unverified on a real iPhone.
- **Declination before calibration**: headings are magnetic; WMM2025
  declination is applied first, then the user's calibration (yaw about the
  vertical, pitch about the camera's own x axis).
- **Refraction** is applied to everything drawn (stars, planets, satellites),
  geometric elevations everywhere else.
- **Trains** are found per frame, not precomputed: satellites from one launch
  (international designator prefix) within 120 days, sunlit, within 7° of a
  neighbour and moving within 25° of the same direction, at least four
  (`core/trains.ts`). Lit members count even when the magnitude filter hides
  them individually, because a train is seen as a whole line. The passes
  list's Trains tab chains same-launch visible passes that start within
  3 minutes of each other, from launches in the last 30 days.
- **Visible-pass searches only run in the dark** (`findVisiblePasses`): the
  Sun-below-limit intervals, widened by 30 minutes so twilight-straddling
  passes are found whole. About 1.7× faster; same passes to 0.25 s.
- **"What's that?"** (`core/identify.ts`, `Engine.identify`) compares the
  path the camera followed for 5 s with each lit candidate's predicted path
  within 40° and brighter than mag 8, after removing a constant
  heading/pitch offset. The score is a chi-square: residual / 0.5°, heading
  offset / 10° (4° within 2 h of calibrating, 30° without a compass), pitch
  offset / 3°, plus a faintness penalty. Geostationary satellites barely
  move, so only position separates them; the UI says "not moving" below
  0.6° of motion.
- **No IndexedDB**: the service worker's caches hold the data; settings are a
  small validated JSON in localStorage.

## Gotchas

- `node scripts/*.ts` needs Node ≥ 22.18 (type stripping on by default).
- Port 5199 on this machine is taken by another project's server; the e2e
  preview uses 4318.
- satellite.js's optional WASM build makes Vite warn about Node built-ins;
  `quietSatelliteWasm()` in `vite.config.ts` resolves them as external for
  that importer only. It must be in `worker.plugins` too — the worker bundle
  has its own plugin list.
